# Tinos3 Agent Guide

Instructions for AI agents contributing to Tinos3.

## Following Cosmos Documentation

Tinos3 is not a typical C# 14 project targeting the .NET 10 SDK. It is an operating system built on the CosmosOS Gen3 project:

- Repository: https://github.com/CosmosOS/Cosmos
- Cosmos Gen3 user wiki: https://cosmosos.github.io/v3.0.96/index.html

**IMPORTANT: Use the Cosmos user wiki, not the developer wiki, when looking up APIs and instructions for OS development.**

Do not assume that standard .NET APIs, runtime behavior, or development workflows are supported by Cosmos. Inspect the existing code and consult the appropriate Cosmos documentation before introducing APIs or changing system behavior.

## Changing Code

- Only change what the task requires.
- Avoid unrelated refactoring, formatting churn, and opportunistic rewrites.
- Follow the existing coding style and project conventions.
- Do not claim that code builds or works unless the relevant verification was actually performed.
- If something cannot be verified, state that explicitly.

## Current Projects (Modules)

- `Tinos3`: The OS kernel.
- `Tinos3.Abstractions`: Shared abstractions and declarations used by other projects.
- `Tinos3.FS`: Filesystem-related functionality.
- `Tinos3.Scripts`: Scripts bundled into the kernel image.
- `Tinos3.Shell`: The shell, which executes a Lua script from `Tinos3.Scripts`.
- `Tinos3.Api`: Multi module APIs like from `Tinos3.Graphical`
- `Tinos3.Graphical`: Graphical stuff

Use these module boundaries when deciding where new functionality belongs. Inspect existing implementations before adding or moving code between projects.

## Respect Existing Code and Architecture

Inspect existing implementations and patterns before introducing new abstractions, dependencies, or alternative approaches.

**`Tinos3.Shell` must not be modified without explicit authorization.**

Do not bypass existing abstractions or duplicate functionality without a clear reason. If a task appears to require architectural changes, explain why and request authorization before proceeding.

## Review Generated Code Critically

Review all changes, whether written manually or generated by an AI agent.

Check:

- Error handling and failure paths.
- Resource lifetimes and cleanup.
- API contracts, parameter types, and return values.
- Edge cases and invalid input.
- Compatibility with Cosmos Gen3 and Tinos3's existing architecture.

Do not assume that generated code is correct simply because it looks plausible or compiles.

## Contributing and Committing

- Do not commit, push, create pull requests, change public interfaces, or introduce dependencies without appropriate authorization.
- If authorized to create a commit, **prefix the commit message with `[AGENT]`** and use Gitmoji in the commit.
- Keep commits focused on the requested changes.
- Never include unrelated changes in a commit.
- Do not discard or overwrite existing user changes.
